# Changelog — Pending Commit

**Branch:** `main`  
**Date:** 22.04.2026  

<br>

# Objective

Major feature release in two phases.

**Phase 1 (14.04.2026)** — **organization workspaces**, **collaborative spreadsheets**, a **redesigned settings system**, **multi-currency support**, a **new design system (PRISM + button variants)**, and **org-aware data isolation** across all financial models. Also removes deprecated code, adds new UI primitives, and updates documentation.

**Phase 2 (22.04.2026)** — **security hardening and encryption redesign**: replace the bespoke "adaptive" password hashing with a clean scrypt-based scheme, fix multiple critical auth/authorization findings (OAuth session bypass, bank-connection IDOR, proxy signature verification), require real secrets at boot, add HTTP security headers, add rate limiting to password flows, add performance indexes to hot query paths, and delete all users except the admin to migrate to the new hashing cleanly.

<br>

### Details:

- Every financial model (`BankAccount`, `Transaction`, `Bill`, `Budget`, `FinancialGoal`, `Notification`, `PACERule`, `SaltEdgeConnection`, `SpreadsheetDocument`) now has an optional `organizationId`. When `null`, the record is personal; when set, it belongs to the org.
- `lib/data-access.ts` provides transparent query scoping so API routes don't need manual org filtering.
- `lib/permissions.ts` enforces plan limits (free: 5 members, 1 bank connection, 10 PACE rules; pro: 50/10/100; enterprise: unlimited).
