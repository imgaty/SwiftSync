# Pre-Commit Checklist

This file specifies all checks and actions to perform before committing changes. Run this workflow each time before pushing to ensure code quality, completeness, and security.

## 1. Identify Changed Files

- [ ] Run `git status` to list all modified, added, and deleted files
- [ ] Record the changes for the commit documentation

## 2. Code Quality Checks

- [ ] Run linter: `npm run lint` — fix any errors or warnings
- [ ] Check TypeScript: `npm run typecheck` — no type errors
- [ ] Verify no console.log or debug statements remain
- [ ] Ensure no commented-out code blocks left behind

## 3. Verify File Structure

- [ ] Compare the file structure in the commit against the documented structure in `TECHNICAL_README.md` or commit doc
- [ ] Ensure no files are missing that should be committed
- [ ] Ensure no unnecessary files are staged (check `.gitignore` is respected)

## 4. Build & Runtime Checks

- [ ] Run `npm run build` — must complete without errors
- [ ] Run `npm run dev` — start dev server to verify no runtime crashes
- [ ] Quick smoke test: navigate to `/login` and `/register` pages, verify they load

## 5. Security: Remove Sensitive Data

- [ ] Identify all `.env` files, API keys, and secrets in code:
  - Check `lib/adaptive-encryption.ts` for hardcoded peppers — should use env vars
  - Check `lib/encryption-v2.ts` for hardcoded keys — should use env vars
  - Check all OAuth configurations — keys should be in `.env`
  - Check `prisma/seed.ts` if exists — no API keys in seeds
- [ ] Create a backup of `.env` and `.env.local` if present
- [ ] Remove all sensitive values from committed files (replace with `process.env.VARIABLE_NAME`)
- [ ] Update `.env.example` with blank templates for sensitive vars
- [ ] Verify `.env` files are in `.gitignore`

## 6. Test Changes

- [ ] Run any relevant test suites: `npm test` (if tests exist)
- [ ] Manually verify new features or changes work as expected
- [ ] Check database migrations applied cleanly (if schema changed): `npx prisma migrate status`

## 7. Commit Documentation

- [ ] Gather all changed files from step 1
- [ ] Write a commit documentation file following the format:
  - **Filename:** `commits/commit(HASH) - ISO-DATE.md`
  - **Header:** `# Changelog Commit \`HASH\`` with Branch, Date, Commit hash
  - **Objective:** Brief summary of what was changed and why
  - **Changes:** Detailed list of file changes, reasons, GitHub links (if applicable)
  - **Summary Table:** Quick reference table of all changed files
- [ ] Include examples (if applicable) — use real output if code-generated examples are needed
- [ ] Save to `commits/` folder

## 8. Verify Docs Are Updated

- [ ] Check `README.md` if it needs updates (feature changes, tech stack updates, etc.)
- [ ] Check `TECHNICAL_README.md` if it needs updates (architecture or security changes)
- [ ] Check `SETUP_GUIDE.md` if setup instructions changed (new env vars, new steps, etc.)
- [ ] Check `docs/` folder files for accuracy

## 9. Re-Add Sensitive Data

- [ ] Restore `.env` and `.env.local` from backup (step 5)
- [ ] Verify sensitive files are NOT staged: `git status` should not show them
- [ ] Verify `.gitignore` is protecting them: `git check-ignore -v .env` should return a match

## 10. Final Pre-Commit Verification

- [ ] Run `git status` one more time — only intended files are staged
- [ ] Run `git diff --staged` — review all staged changes for correctness
- [ ] Verify commit message follows format: `type: description` (e.g., `docs: improve README`, `feat: add 2FA flow`, `fix: password hashing edge case`)
- [ ] Check if multiple commits are needed or if everything should be squashed

## 11. Commit

- [ ] Run `git commit -m "type: description"` 
- [ ] If commit docs were created, add them separately: `git add commits/ && git commit -m "docs: add commit documentation for HASH"`

## 12. Post-Commit

- [ ] Run `git log --oneline -5` — verify commits appear correctly
- [ ] Run `npm run build` one final time on the committed state
- [ ] Ready to push: `git push`

---

## Quick Command Reference

```bash
# Check status
git status

# Lint and type check
npm run lint
npm run typecheck

# Build
npm run build

# Dev server
npm run dev

# View staged changes
git diff --staged

# Commit
git commit -m "type: description"

# View recent commits
git log --oneline -5
```

---

## Notes

- **API Keys / Secrets:** Always remove before committing. Use `.env.example` and `process.env.VARIABLE` in code.
- **File Structure:** Compare against documented structure in commit docs or README
- **Commit Message Format:** Keep it concise, use `type: description` format
- **Test Before Pushing:** Never push without running `npm run build` successfully
